# PCS 스케줄 자동 수집 · 달력 뷰어

PCS LINE e-service(ebiz.pcsline.co.kr)의 **스케줄 > 구간별** 화면을 자동으로 조회해서
모선 정보를 저장하고, 날짜·오전/오후를 골라 달력으로 보는 프로그램입니다.

---

## 1. 처음 한 번만 설정

### (1) 계정 입력
`config.json` 을 메모장으로 열어 아이디/비밀번호를 채웁니다.

```json
{
  "login": {
    "enabled": true,
    "user_id": "내아이디",
    "password": "내비밀번호"
  },
  ...
}
```

> 계정을 비워두면 **비로그인 상태로 수집**합니다. 확인해 보니 구간별 스케줄 조회는
> 비로그인으로도 동작하지만, 로그인 시 보이는 정보가 다를 수 있으므로 계정 입력을 권장합니다.
> 비로그인으로 수집된 데이터는 뷰어 상단에 주황색 안내가 표시됩니다.

### (2) 조회할 항로
같은 파일의 `routes` 에 출발/도착 포트 코드를 적습니다. 지금은 4개가 들어 있고,
줄을 추가하면 몇 개든 늘릴 수 있습니다.

```json
"routes": [
  { "pol": "CNSHA", "pod": "KRINC" },
  { "pol": "CNSHA", "pod": "KRPUS" },
  { "pol": "CNNGB", "pod": "KRINC" },
  { "pol": "CNNGB", "pod": "KRPUS" }
]
```

기타 설정
| 항목 | 설명 |
|---|---|
| `months_ahead` | 이번 달부터 몇 개월치를 조회할지 (기본 3) |
| `headless` | `false` 로 두면 수집할 때 브라우저 창이 보입니다 |
| `viewer_port` | 뷰어 주소의 포트 번호 (기본 8777) |

### (3) 자동 실행 등록
`install_task.ps1` 을 **우클릭 → PowerShell에서 실행**.
Windows 작업 스케줄러에 2개가 등록됩니다.

| 작업 이름 | 시각 | 저장 이름 |
|---|---|---|
| `PCS_Schedule_AM` | 매일 09:00 | `2026.09.18 오전` |
| `PCS_Schedule_PM` | 매일 18:00 | `2026.09.18 오후` |

---

## 2. 매일 쓰는 법

- **달력 보기** — `run_viewer.bat` 더블클릭 → 브라우저가 자동으로 열립니다.
  (검은 창은 켜 둔 채로 두세요. 닫으면 뷰어가 꺼집니다.)
- **지금 바로 다시 수집** — `run_scrape.bat` 더블클릭. 현재 시각이 12시 전이면 오전,
  이후면 오후 스냅샷으로 저장됩니다.

### 뷰어에서 할 수 있는 것
- **조회 날짜** + **오전/오후** 선택 → 그때 수집했던 모선 데이터가 달력에 표시됩니다.
  (수집 기록이 없는 시간대는 버튼이 흐려집니다.)
- **항로 칩**을 눌러 항로별로 켜고 끄기 — 항로마다 색이 다릅니다.
- **기준**을 출항일(ETD) / 도착일(ETA) 로 전환.
- **검색**으로 선명·항차·노선코드 필터.
- 모선을 클릭하면 선명 / 항차 / 노선코드 / ETD / ETA / 직항·환적 / 마감 여부가 뜹니다.
- 마감된 모선은 취소선으로 표시됩니다.

---

## 3. PC가 꺼져 있었다면

작업 스케줄러에 **"놓친 작업 실행"(StartWhenAvailable)** 을 켜 두었습니다.
09:00에 PC가 꺼져 있었다면 켜진 직후 자동으로 수집하고, 이때도 이름은 예약된
시간대(**오전**)로 저장됩니다. 실패 시 10분 간격으로 3회까지 재시도합니다.

> PC 전원과 완전히 무관하게 돌리려면 클라우드(GitHub Actions 등)로 옮겨야 합니다.
> 지금 구조 그대로 옮길 수 있으니 필요하면 말씀 주세요.

## 4. 데이터가 저장되는 형태

`data/2026-09-18_AM.json`

```json
{
  "snapshot": "2026.09.18 오전",
  "date": "2026-09-18",
  "session": "AM",
  "collected_at": "2026-09-18 09:00:12",
  "logged_in": true,
  "routes": [
    {
      "pol": "CNSHA", "pod": "KRINC",
      "pol_name": "SHANGHAI, CHINA", "pod_name": "INCHEON, KOREA",
      "ok": true,
      "vessels": [
        {
          "label": "PEGASUS GLORY 2621E",
          "vessel": "PEGASUS GLORY",
          "voyage": "2621E",
          "vslvoy": "DPGL2621E",
          "route": "ISS",
          "etd": "2026-09-04 16:00", "etd_date": "2026-09-04",
          "eta": "2026-09-06 05:30", "eta_date": "2026-09-06",
          "direct": true, "closed": false
        }
      ]
    }
  ]
}
```

`label` 이 요청하신 표기입니다 — **선명 + 항차코드(9자리) 뒤 5자리**.
예) `DONGJIN VENUS` + `JDJV0335N` → `DONGJIN VENUS 0335N`

과거 스냅샷은 지우지 않는 한 계속 쌓이고, 뷰어의 날짜 목록에 그대로 나옵니다.

## 5. 수집 방식에 대한 메모

`scraper.py` 는 요청하신 순서 그대로 화면을 조작합니다.
사이트 접속 → LOGIN → 로그인 → 스케줄 → 구간별 → 출발지 입력(코드 입력 후 **Tab**)
→ 도착지 입력 → Inquiry.

다만 **달력의 모선을 하나씩 클릭하는 대신**, Inquiry 버튼이 실제로 주고받는
`/sch/selectScheList` 응답을 그대로 읽습니다. 이 응답에는 개별 클릭 시 나오는
`선명 · 항차 / ROUTE`(`VSL_NAME` + `VSLVOY`)와 출항일시(`EXPORT_DT`+`EXPORT_HH`)가
똑같이 들어 있어, 결과 값은 동일하면서 훨씬 빠르고(4항로 3개월 약 75초) 안정적입니다.
클릭 방식이었다면 모선 170여 건을 하나씩 눌러야 해서 20분 이상 걸립니다.

---

## 6. 문제가 생기면

- `logs/scrape_2026-09.log` 에 수집 기록이 남습니다.
- 브라우저 동작을 눈으로 보려면: `run_scrape.bat --show`
- 로그인이 실패하면 로그에 `로그인 실패` 가 찍히고 수집이 중단됩니다.
  아이디/비밀번호 또는 회원승인 상태를 확인하세요.
- 특정 항로만 실패하면 나머지는 정상 저장되고, 뷰어 상단에 실패 항로가 표시됩니다.
- 사이트 화면 구조가 바뀌면 `scraper.py` 위쪽 `--- 화면 element ---` 부분만 고치면 됩니다.

## 7. 수동 실행 명령

```
python scraper.py                # 지금 시각 기준 수집
python scraper.py --session AM   # 오전 스냅샷으로 저장
python scraper.py --session PM   # 오후 스냅샷으로 저장
python scraper.py --show         # 브라우저 창 띄우고 수집
python server.py                 # 뷰어 실행
python server.py --port 9000     # 포트 바꿔서 실행
```
